Retryable GET

Named checkpoints

A long-running read-only stream can mark completed stages. If the connection drops, the browser retries the GET with the last acknowledged checkpoint and the action continues from there.

+page.py 
from hyperdjango import Checkpoint, HTML, action, get_resume_checkpoint


class PageView(HyperView):
    @action(method="GET")
    async def build_report(self, request):
        stages = ("catalog-loaded",)
        resume = get_resume_checkpoint(request, allowed=stages)

        if resume is None:
            yield HTML("Catalog loaded", target="#report", swap="append")
            yield Checkpoint("catalog-loaded")

        # On retry, catalog-loaded is returned above and this block is
        # not executed again. Continue from shared, reconstructible state.
        yield HTML("Pricing calculated", target="#report", swap="append")
        yield HTML("Report ready", target="#report", swap="append")

Checkpoint contract

A checkpoint means the browser processed every preceding frame. It is an untrusted progress hint—not authorization or exactly-once execution—so authenticate every retry and keep work before each checkpoint safe to repeat.
